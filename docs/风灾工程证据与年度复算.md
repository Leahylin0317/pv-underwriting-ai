# 风灾工程证据与年度复算接口

本功能对应《光伏核保项目推进与验收计划》（2026-10-11）的第一个灾种闭环。当前实现可用提交的厂家和工程证据核验安装适用性，并在有完整、同口径年度压力序列时计算历史比较指标。**它不自动生成保险等级、加费系数或承保结论。** 这些映射仍需业务方确认来源和适用条件。

## 输入位置

真实整单接口 `POST /api/v1/underwriting/analyze` 与异步任务接口 `POST /api/v1/underwriting/jobs` 的 `manifest` JSON 可增加 `wind_evidence`。省略此字段时保持原有保守流程。输入会保存到 `UnderwritingCase.wind_evidence`，计算结果保存到 `UnderwritingCase.catastrophe_assessment.wind_comparison`，Markdown 报告展示来源、年度排除原因、R/F 和待补缺口。

  "case_id": "EXAMPLE-ONLY",
  "project": {"...": "沿用现有 ProjectInfo 字段，component_model 必须是完整型号"},

  "wind_evidence": {
    "component_model": "EXAMPLE-MODEL-1000",
    "manufacturer": "示例厂商",
    "manual_url": "https://example.org/manual.pdf",
    "manual_version": "v1",
    "manual_page": "8",

## 计算条件与结果

1. 安装方式明确匹配厂家手册，有可定位材料编号、核验人和时间；不匹配为 `not_applicable`，无结论为 `pending_confirmation`。
2. 项目位置有交叉核验证据；年度值已按经工程确认的方法转换成与厂家能力相同定义的 **Pa**。Open-Meteo 的 10 米阵风 `m/s` 不能直接当作屋面风压，也不能由本接口自动乘常数后用于正式核保。历史天气可保留为气候背景。[Open-Meteo 官方接口文档](https://open-meteo.com/en/docs/historical-weather-api)列有风速和阵风变量，并说明数据为再分析产品。
3. 每年只在 `valid_days == expected_days` 且 `maximum_pa` 非空时纳入；`expected_days` 必须与闰年一致。缺测年份逐项列出，不填零。当前技术口径只接受完整年份；如业务拟接受部分年度，须先确认完整性标准并更新版本。
4. 有效年份至少一个时，`R = 完整年度历史最大工程风压 / 经核验组件能力`；`F = 超过组件能力的完整年份数 / 有效完整年份数 × 100%`。等于能力值不计“超过”。有效年份为零时两项均不计算。
5. 返回 `calculated`、`incomplete` 或 `incompatible`，并保留每年的来源、网格、有效天数和排除理由。`technical_result` 仅表示本次历史样本是否有超过能力的年份。它既非实际出险概率，也不证明整套电站结构安全。

即使风灾已复算，冰雹、积雪及保单动作仍会保持待核验；正式案件的综合抗灾等级继续为 `unknown`，整单转人工。这避免在业务分级规则未确认时由演示能力比擅自给出承保建议。实验室旧能力比与本次 R/F 是不同指标，不能交叉套用阈值。

## 真实验收需要补齐

- 一套真实项目的完整型号和铭牌、厂家原始 Datasheet/安装手册及版本页码。
- 现场安装近照或验收记录，固定点、夹持区、支撑和受力方向的工程核验人。
- 经核验的项目坐标及工程风压年度序列，数据集、实际网格、单位、转换方法、有效日数和来源文件。
- 业务批准的等级和动作映射、规则版本、确认人及生效日期。当前仓库没有这些正式依据，不能把模拟复算结果当作真实样例通过。

建议先对一套真实材料手工复算，再由系统运行同一输入，对照每年入选记录、R/F、安装适用性和报告证据；接口失败、型号不符和年度缺测分别保留首轮运行记录。
